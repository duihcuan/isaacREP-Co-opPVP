# 真实测试协作说明

本目录存放 PVP Arena 模组的**真实测试产出物**（区别于 `docs/testing/samples` 风格的教学样例）。

## 目录结构

```
docs/testing/
├── README.md            ← 本文档：我们怎么配合
├── test-plan.md         ← RT-01 测试计划
├── test-cases.md        ← 用例库 + 执行结果（会随每次会话更新）
├── bugs.csv             ← 缺陷台账
├── traceability.md      ← 需求跟踪矩阵
├── evidence/            ← 原始证据（游戏日志的存档副本）
└── test-reports/        ← 每轮结束后的报告
```

## 分工：你负责玩，我负责记录与判定

| 环节 | 谁做 | 说明 |
|---|---|---|
| 环境准备（构建、记录 commit、备份日志） | AI | 每次会话开始前完成 |
| 实机操作（手柄、按键、对局） | **你** | 只有你能做 |
| 证据采集（读日志、存证、解析） | AI | 会话结束后立刻执行 |
| 用例判定（通过/失败/阻塞） | AI 给出初步判定，你复核 | 有分歧时以你的实机感受为准，但要能在日志里找到对应痕迹 |
| 缺陷登记 | AI 起草，你确认严重度 | 严重度最终由你拍板 |
| 报告与准出结论 | AI 起草，你签字 | 你是测试负责人 |

## 每次会话的标准循环

```
1. AI：确认构建版本、备份并清空日志基线
2. 你：按会话脚本实机操作（约 10-20 分钟）
3. 你：说一声"测完了"
4. AI：立刻把 log.txt 存进 evidence/，解析成用例结论，更新用例库与缺陷台账
5. AI：给出下一场会话的脚本
```

**关键纪律：每次会话结束后立刻存证。** 游戏每次启动都会**覆盖** `log.txt`，如果你连玩两次再告诉我，第一次的证据就永久丢失了。
