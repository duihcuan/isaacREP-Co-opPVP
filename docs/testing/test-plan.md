## 1. 测试目标

验证 M1 版本的 PVP 核心循环在本地双人环境下能否完整跑通，并回答三个问题：

1. 两名玩家能否稳定进入对局并分出胜负？
2. 竞技场约束（房间锁定）是否真的不可突破？
3. 模组在真实双人操作下的表现与设计是否一致？

## 2. 范围

**本轮测试**：模式与状态机、房间与锁定、互伤、结算、角色白名单、兼容与隔离（共 32 条用例，见 `test-cases.md`）。

**本轮不测**：

| 内容 | 原因 |
|---|---|
| M2 自定义血量池与自绘血条 | 未实现 |
| M3 道具争抢与黑名单 | 未实现 |
| M4 平衡性与 Mod Config Menu | 未实现 |
| 在线合作 | 不在 v1 范围 |
| 成就与存档统计影响 | 已确认为 v1 接受的风险 |

## 3. 已知阻塞（本轮无法消除）

**PVP 模式开关尚未实现。** 只要模组启用，任何一局 run 都会进入 PVP 对局。因此"非 PVP 场景与原版一致"这类用例（TC-029、TC-030）**无法构造前置条件，只能标记为阻塞**。

这是真实测试中常见的形态：**不是所有用例都能执行，阻塞必须如实记录，绝不能记成通过。**

## 5. 测试仪器（可观测性）

**首次真实测试暴露了观测缺口**：原日志只能证明"判定命中了"，无法证明"伤害真的生效、玩家真的出局"。为此在 `115d4e2` 中补充了四类埋点：

| 日志前缀 | 含义 |
|---|---|
| `[PVP] 血量变化 P1/P2: a → b` | 玩家血量发生变化（证明伤害真的生效） |
| `[PVP] 出局状态变化 P1/P2: false → true` | 玩家死亡或变为幽灵 |
| `[PVP] 命中 P1→P2 伤害=N(半心) 目标伤害前=M 攻击实体类型=T` | 一次 PVP 命中的完整信息 |
| `[PVP] 检测到离场：当前房间=X 竞技场=Y P1位置=(..) P2位置=(..) 已请求拉回` | 有人离开了竞技场，含房间号与坐标 |

**这是真实测试最重要的产出形态之一：测试不仅发现产品缺陷，还会发现"验证能力不足"，从而推动补埋点。**

## 6. 准入 / 准出标准

**准入**：`npm run lint` 与 `npx vitest run` 通过；构建成功且记录了 commit；冒烟测试可执行。

**准出**：

1. 可执行用例通过率 100%（阻塞项需记录原因）。
2. S1、S2 级缺陷为 0。
3. 兼容性必测行执行完毕。
4. 测试报告产出并签字。

## 8. 风险

| 风险 | 应对 |
|---|---|
| 日志每次启动被覆盖，早先证据丢失 | 每次会话结束立即存证到 `evidence/` |
| 无道具时无法测试炸弹/传送/激光类场景 | 用控制台给道具，并在用例里记录所使用的道具名 |
| 帧级边界（平局 3 帧）人工难以精确复现 | 允许多次尝试，记录复现率而非"必现" |
| 单人兼任开发与测试，容易在测试中途改代码 | 会话期间不改代码；改动一律另开会话 |
