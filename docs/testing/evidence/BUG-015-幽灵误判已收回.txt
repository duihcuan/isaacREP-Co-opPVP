BUG-015 证据：输家的道具永远清不掉（赢家能清）
==============================================

用户实测反馈（构建 ea0256e）：

"当 1p 拾取了道具被 2p 击杀后道具不会清空会保留到下一回合；无论是 1p 击杀 2p
还是 2p 击杀 1p，旧拾取的道具都不会清空。但是 1p 击杀 2p 时，1p 在这回合拾取的道具
会清空，之前回合因为 2p 击杀所保留的道具不会清空。"

提取出的规律：

1. 赢家（存活一方）本回合捡到的道具 → **能清掉**。
2. 输家（变成幽灵的一方）捡到的道具 → **清不掉**，带到下一局。
3. 一旦某件道具漏掉一次，之后**永远不会再被清理**。

根因：

收回函数在还有幽灵玩家时仍然按 `HasCollectible` 重新计算待收回清单：

    pendingRevoke = itemsStillHeld(pendingRevoke, stillHeld);

而 co-op 幽灵状态下玩家往往**根本不报告**持有这些道具（引擎把它们的物品留到复活时恢复）。
于是 stillHeld 为空 → 待收回清单被误判成"已清空" → 之后不再重试；
等玩家被复活、引擎把道具恢复回身上时，已经没有任何清单可以依据了。

这同时解释了规律 1（存活玩家确实被移除）、规律 2 与规律 3（幽灵被跳过判定、且清单已空）。

修复（构建 81a1a03）：

只要有任意玩家处于幽灵状态，就**不缩小清单**，只记录进度并等待复活：

    if (anyGhost) { 记录进度; return; }
    ...
    pendingRevoke = itemsStillHeld(pendingRevoke, stillHeld);
    if (pendingRevoke.length === 0) { 记录"上一局道具已全部收回"; }

复活后（ChangePlayerType 那一级生效）的同一帧就会执行移除并确认，
因此输家的道具会在下一局开打前被真正清掉。

已知限制：

若某件道具在后续回合被合法地重新刷出并被拾取，而它仍留在待收回清单里，
会被一并移除。宝物池道具数量很大，连续两局刷到同一件道具的概率极低，暂时接受。
